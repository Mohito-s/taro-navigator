## СДЕЛАНО (реализовано, проверено)

- [x] Профиль (вкладка `screen-profile`): баланс Stars, выбор стиля
      интерпретации из 5 образов (Космо, Гендальф Серый, Доктор Стрэндж, Мастер
      Йода, Дамблдор), знак/арканы из сохранённой карты. Стиль хранится в
      `localStorage` (`taro_style`) и шлётся боту `{type:"style"}`.
- [x] Бот: убран персистентный `MenuButtonWebApp` — вместо него мини-апп
      открывается обычной кнопкой «🪐 Мини-апп» в меню /start (иначе стандартное
      меню чата исчезало). В приветствие добавлена заглушка будущей группы.
- [x] БД: колонка `style` в `users` (дефолт `cosmo`) + миграция
      `ALTER TABLE` для существующих таблиц; обработчик `type:"style"` с
      allowlist из 5 стилей.
- [x] Мини-апп: 5 вкладок (Расклады/Натал/Прогноз/История/Профиль), нижний
      glass-таббар, переключение экранов.
- [x] Натальная карта = фундамент: форма сохраняет карту в `localStorage`
      (`taro_natal`), подставляет в калькулятор, шлёт боту `{type:"natal"}`,
      бот сохраняет профиль и отвечает главным меню.
- [x] Отправка в бота из мини-аппа устойчива к поздней инициализации Telegram
      WebView: `taroSend()` кладёт данные в очередь, `initTelegram()` флашает её.
      `__taroCanSend` больше не зависит от `initData` (в некоторых клиентах он
      пустой) — флаг ставится по наличию WebApp-объекта. (`js/app.js`)
- [x] Описание бота (set_my_description / set_my_short_description).
- [x] БД: таблица `users`, UPSERT по `telegram_id` (повторный сейв обновляет,
      а не дублирует), `full_report_paid`. Проверено: реальная запись ikodq
      (tg 830960097) на 25.09.1985 → знак Весы, город шкуринская.
- [x] Оплата Telegram Stars (инвойс XTR) + TEST_MODE (отправляет разбор без
      оплаты).
- [x] 3D-космос: сцена Three.js (луна/звёзды/метеоры), объёмные арканы-карты,
      натальный диск SVG со звёздами.
- [x] Безопасность: эхо `city`/`time` в HTML-ответе бота экранируется
      (`html.escape` в `bot/handlers/webapp.py`), репорт уже экранировал.
      Security-аудит: 0 секретов во фронте, `.env`/`taro.db` не в git, нет
      f-string SQL и `subprocess`.
