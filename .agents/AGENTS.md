# AGENTS.md — правила для всех агентов в этом репозитории

Эти правила применяются к любому агенту (основному или субагенту) перед тем,
как он пишет или меняет код.

## 1. Сначала прочитай журнал проекта

Перед ЛЮБЫМ изменением кода прочитай **`PROJECT_STATE.md`** (корень репозитория):
- раздел **ПЛАН** — что запросил пользователь и чего ещё нет;
- раздел **ЛОГ ИСПРАВЛЕНИЙ** — что уже было сделано/исправлено;
- раздел **СДЕЛАНО** — что уже реализовано.

## 2. Никакой самодеятельности

- Работай только над тем, что пользователь явно попросил в текущем диалоге
  или что помечено в «ПЛАН» журнала.
- Если задача уже сделана или уже в плане — не дублируй, сообщи пользователю.
- Если задача не из плана и не из явной просьбы — спроси, прежде чем делать.
- Не меняй дизайн/тексты/поведение без запроса. Константы проекта:
  русский язык, «ты»-форма, **Dark Luxury Gold** стиль:
  - Фон: угольно-чёрный `#111114`, карточки `#1c1c20` / `#232328`
  - Акцент: тёплое золото `#c9a96e`, крем `#e8dcc8`, свечение `rgba(201,169,110,0.2)`
  - Текст: `#f0ece4` основной, `#8a857c` muted
  - Рамки: `rgba(201,169,110,0.18)` gold-border
  - Шрифты: **Playfair Display** (заголовки, serif), **Inter** (body, sans)
  - Карточки: плотные тёмные с тонкой золотой рамкой, БЕЗ glassmorphism/blur
  - Эффекты: минимальные тени, без неоновых свечений, тонкие gold-hover
  - Иллюстрации: сгенерированные арт-изображения карт Таро (vintage/мистика)
  - Без картинок из интернета. Иконки — SVG или сгенерированные ассеты.

## 3. После работы — обнови журнал

Перенеси выполненный пункт из «ПЛАН» в «СДЕЛАНО» и добавь запись сверху в
«ЛОГ ИСПРАВЛЕНИЙ» (формат: `ДАТА — что сделано (где)`). Проверь фикс перед
записью (lint/run/test). Изменения в `PROJECT_STATE.md` коммить вместе с кодом.

## 4. НИКОГДА не ломай кодировку UTF-8 (частая авария проекта)

Все файлы с русским текстом (`index.html`, `css/style.css`, `js/*.js`,
`*.md`, `bot/*.py`) — **UTF-8 без BOM**. Их ломает любой перезапуск через
Windows-оболочку. Жёсткие правила:

- **ЗАПРЕЩЕНО** читать/писать такие файлы через PowerShell:
  `Get-Content`, `Set-Content`, `Out-File`, `-replace` в конвейере,
  `(Get-Content -Raw) ... | Set-Content`. Даже `Set-Content -Encoding utf8`
  в Windows PowerShell 5.1 перекодирует кириллицу в моджабу (`ÐÑÐ»ÐµÐ½...`)
  и/или ставит BOM.
- **Можно и нужно** использовать:
  - инструмент `Edit`/`Write` (безопасен, сохраняет UTF-8);
  - `node --check` / `python` с явным `encoding="utf-8"` для чтения/проверки;
  - `python -m py_compile`.
- Если файл всё-таки нужно переписать потоком — делай это скриптом с явным
  UTF-8 (например Python `open(f, "w", encoding="utf-8", newline="\n")`), но
  лучше всего править точечно через `Edit`.
- Перед коммитом веб-файлов **обязательно** проверь кодировку:
  `python -c "raw=open('index.html','rb').read(); print(raw[:3]==b'\xef\xbb\xbf', raw.decode('utf-8','replace').count(chr(0xFFFD)))"`
  должно быть `False 0`. Если 0xFFFD или «Ð/â€”» появились — файл побит, чини
  (восстанови из git и нанеси правки заново через `Edit`).
- Команды `git checkout <commit> -- <file>` для восстановления — безопасны.

## 5. Проект в двух словах

- **Open-source** проект (лицензия MIT) с планами на постепенную монетизацию
  (Telegram Stars freemium, донаты) после набора аудитории.
- `bot/` — aiogram 3 Telegram-бот, SQLite `data/taro.db`, Stars-оплата, ИИ-провайдеры.
- `api/` — FastAPI мини-апп API (ИИ-разборы прямо в вебе, rate-limit, HMAC).
- `index.html` + `natal.html` + `forecast.html` + `profile.html` — 4-страничный
  сайт/мини-апп, стили в `css/style.css`, логика в `js/app.js`.
- `js/space.js` — Three.js фоновая сцена (звёзды, луна).
- `js/natal.js` — астрономический движок (VSOP87 эфемериды).
- `img/cards/` — сгенерированные иллюстрации 22 старших арканов Таро.
- Сайт хостится на `shadowlinkapp.online` (VPS nginx) + GitHub Pages (запасной).
- Подробнее по направлениям — навыки в `.agents/skills/`.

## 6. Строгий протокол развертывания (Deployment Protocol)

У нас есть слабый VPS (`roman@213.21.240.231`), поэтому мы минимизируем прямую сборку на сервере.
Пайплайн работы:
1. **Local Dev**: Вся разработка и изменения кода делаются только на локальном компьютере.
2. **Local Testing**: Обязательно проверяем изменения локально (линтеры `flake8`/`ruff`, тесты в браузере).
3. **GitHub Sync**: Коммитим стабильный код в основную ветку и пушим на GitHub (`Mohito-s/taro-navigator`).
4. **Server Deploy**: Заходим на VPS по SSH, переходим в `~/apps/taro-navigator` и делаем `git pull`.
5. **Restart**: Выполняем `pm2 restart taro-bot` (или `taro-api`). Никакой правки кода прямо на проде!
