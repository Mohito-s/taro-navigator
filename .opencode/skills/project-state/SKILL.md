# Project State Discipline (TARO)

Единый журнал проекта живёт в **`PROJECT_STATE.md`** (корень репозитория).
Он — источник правды о том, что запланировано, что сделано и что было исправлено.

## Обязательное правило перед ЛЮБЫМ кодом

1. **Прочитай `PROJECT_STATE.md` целиком** (разделы ПЛАН / СДЕЛАНО / ЛОГ ИСПРАВЛЕНИЙ).
2. **Не начинай новую работу, которой нет в «ПЛАН» и которую не запросил
   пользователь** в текущем диалоге. Если задача не из плана и не из явной
   просьбы — остановись и спроси, а не делай по своей инициативе.
3. Если задача уже отмечена как сделанная или уже висит в плане — **не дублируй**:
   скажи пользователю об этом, а не переделывай заново.
4. Перед началом работы отметь пункт плана как `[ ]` → `[x]` или допиши
   комментарий «в работе», чтобы другой агент не начал её параллельно.

## После завершения работы (всегда)

1. Перенеси выполненный пункт из «ПЛАН» в «СДЕЛАНО» (если это была задача из плана).
2. Добавь запись сверху в «ЛОГ ИСПРАВЛЕНИЙ» в формате:
   `ДАТА — что сделано (где: file или file:line).` Пиши по-русски, по делу,
   с конкретными путями к файлам.
3. Проверь фикс перед записью (lint / run / тест), как требует проект.

## Что не делать

- Не создавай и не «улучшай» функциональность, о которой не просили.
- Не меняй дизайн/тексты/поведение без запроса (космос-стиль, «ты»-форма,
  русский язык — константы проекта).
- Не прави чужие pending-задачи, помеченные «в работе» другим агентом, без
  уведомления пользователя.

## Где что лежит (короткая карта)

- `PROJECT_STATE.md` — журнал (читать перед кодом, обновлять после).
- `bot/` — aiogram 3 бот, SQLite `data/taro.db`.
- `index.html` + `css/style.css` + `js/app.js` + `js/space.js` — мини-апп/сайт.
- `.opencode/skills/` — навыки по направлениям (audit, taro-backend,
  frontend-design, mini-app, three-js-scene, browser-verify).
